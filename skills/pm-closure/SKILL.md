# 結案與覆盤

## 檔案位置

```
06-closure/
├── acceptance.md        # 驗收紀錄
└── retrospective.md     # 覆盤報告
```

## 驗收紀錄（acceptance.md）

### 標準格式

```markdown
# [專案名稱] 驗收紀錄

> 驗收日期：YYYY-MM-DD
> 參與者：

## 驗收項目

| # | 功能/交付項目 | 對應規格 | 驗收結果 | 備註 |
|---|--------------|----------|----------|------|
| 1 | | spec.md F-XXX | ✅ 通過 / ❌ 未通過 / ⚠️ 有條件通過 | |
| 2 | | | | |

## 未通過項目處理

（如果有未通過的項目，列出處理方式和時程）

### 項目 X：[名稱]
- **問題描述**：
- **處理方式**：
- **預計完成日期**：

## 驗收結論

- [ ] 全部通過，專案結案
- [ ] 部分通過，待修正後複驗
- [ ] 未通過，需重新處理

## 客戶簽署確認

（客戶確認驗收通過的紀錄：日期、方式、確認人）
```

## 結案流程

1. 與客戶進行驗收 → 產出 `acceptance.md`
2. 驗收通過後 → 撰寫 `retrospective.md`
3. 更新 README.md：
   - 狀態改為「已結案」
   - 填入驗收和結案的實際日期
4. 如果有值得展示的案例 → 整理素材到 `_company/portfolio/`
5. 確認所有款項已收齊

## 結案 Checklist

提醒使用者確認以下事項：

- [ ] 所有功能已驗收通過
- [ ] 所有文件已交付
- [ ] 原始碼/資產已移交（如適用）
- [ ] 所有款項已收齊或已約定付款日期
- [ ] 保固/維護條款已確認
- [ ] 覆盤報告已完成
- [ ] README.md 已更新為「已結案」
- [ ] 有價值的案例已整理到 portfolio
